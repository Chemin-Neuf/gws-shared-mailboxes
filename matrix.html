  • Row 2 (Reply & writing): Collaborative Inbox and Distribution List score +/− rather than NOK only when the admin-enforced Send-As + outbound-compliance workaround is deployed — see Topic 2.
  • Row 3 (Folders & labels): Collaborative Inbox scores +/− because its shared tags are flat (no sub-tags or folder hierarchy) and its resolution statuses are a fixed, non-customizable set — see Topic 3.
  • Row 6 (Identity & signatures): Alias scores +/− (not OK) because, when the alias is shared by several people, each member maintains their own Send-As signature and display name — the same divergence as Distribution List — with the same possible "via" disclosure — see Topic 6.
  • Row 7 (Contacts & directory): Delegation scores +/− (not OK) because recipient autocomplete is disabled in delegated accounts and the mailbox's own contact list is not editable by delegates unless contact delegation is added — see Topic 7.
  • Row 8 (Security & compliance): Distribution List and Send-Mail-As score +/− because individual accountability is only partial: for a list, who replied is not centrally visible, and Send-As mail lives in members' personal Sent folders. MFA, credential exposure and offboarding are clean for both — see Topic 8.
  • Row 9 (Admin controls): Send-Mail-As scores NOK because grants live in each member's own Gmail settings with no admin-console visibility unless centrally provisioned via API; Delegation scores +/− because a tenant-wide delegate inventory requires API reporting — see Topic 9.
  • Row 10 (API & automation): Alias / Redirection scores +/− because aliases are fully scriptable (Directory API) but routing/redirection rules are Admin-console-only — no API exists — see Topic 10.
  • Option 1 (Shared Password) is excluded by security policy regardless of its scores — see Topic 8.
