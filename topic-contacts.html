Topic 7 — Contacts & Directory Access

When a team member writes from the shared identity, whose address book do they get? Personal contacts, the domain Directory, or the shared mailbox's own contact list? This is the topic most comparisons forget — and a real Google Workspace gap.

📅 Last updated: 2026-09-08 ✍️ Chemin Neuf Community · Kimi K3 🏷️ Status: Draft — pending review

On this page

How contacts work in Google Workspace

Three distinct contact sources exist, and they are often confused:

  • Personal contacts — per-account, managed in contacts.google.com. A delegated or shared mailbox has its own personal contacts, separate from each delegate's.
  • Domain Directory — all users and groups of the tenant, plus admin-managed shared external contacts. Autocompletes for everyone when Directory is enabled.
  • Auto-collected "Other contacts" — addresses Gmail remembers from past correspondence, per account.

The structural gap: Google has no native "team address book" for arbitrary external contacts. Shared external contacts live in the Directory and are visible to the whole tenant — you cannot scope them to one team or one mailbox.

Comparison across the 7 options

Option Autocomplete Source When Writing Shared Contact List for the Team Key Caveats
1. Shared Password Account The shared account's own contacts + Directory. Yes, de facto the account's contact list is the team's list Works, but contacts accumulate with no governance; export/backup is manual.
2. Gmail Delegation Account The delegated account's own contacts + Directory. Yes, de facto all delegates share the mailbox's contact list Best native answer to "shared address book for this mailbox". Mobile Gmail app autocomplete included.
3. Collaborative Inbox None in Groups UI replying happens with minimal composer; real writing falls back to Gmail No Contacts are effectively handled by the member's personal Gmail when using Send As.
4. Distribution List Each member's personal contacts + Directory. No every member maintains their own list The classic pain: "does anyone have the supplier's new address?"
5. Email Alias / Redirection The recipient's personal contacts + Directory. N/A single person Appropriate for one-person functions.
6. "Send Mail As" Config The sender's personal contacts + Directory. No Inherits options 4/5 — identity changes, address book does not.
7. Email-to-Google Chat Space N/A no external compose from Chat No External replies via Gmail inherit that option's behavior.

Admin-managed shared external contacts (Directory)

Administrators can add shared external contacts (Admin console → Directory → Directory settings, or the Admin SDK Directory API). These autocomplete for everyone in the tenant in Gmail, Contacts and mobile sync.

Limits relevant to a nonprofit

  • All-or-nothing visibility — no per-team or per-OU scoping of external contacts.
  • No user self-service — only admins (or API scripts) can add them; users cannot contribute.
  • Propagation delay — new shared contacts can take up to 24 h to appear in autocomplete.
  • Quota — the Directory accepts large volumes (hundreds of thousands of external contacts), far beyond nonprofit needs.

Third-party "shared contacts" tools — policy check

A market of add-ons (e.g. Shared Contacts for Gmail-type tools) exists precisely because of the native gap: label-based contact sharing between users. Per the standing nonprofit policy, these are excluded by default (recurring per-user cost, additional vendor access to Directory data). Possible exception: a free tier or a genuinely decisive feature deployed to a small set of power users only. The delegated mailbox's built-in shared contact list (option 2) covers most needs at zero cost.

User perspective

  • Autocomplete expectations. Users expect "type three letters, get the right person". Only Directory entries and the current account's own contacts deliver that — personal contacts of colleagues never autocomplete for you.
  • Delegation surprise. Delegates sometimes search their own contacts while composing in the delegated mailbox and wonder why an address is missing: the mailbox has its own list, which must be fed deliberately.
  • Mobile parity. Contacts sync to phone address books per account; the shared mailbox's contacts only appear if that account is added to the device.

Administrator perspective

Web console

Admins control: Directory visibility (on/off per OU), shared external contacts (add/edit/delete), and contact delegation (a user-level feature letting an assistant manage someone's contacts — rarely used). There is no console UI to push contacts into a mailbox's personal list.

API & automation

Two APIs matter: the Admin SDK Directory API (shared external contacts for the whole tenant), and the People API for per-account personal contacts (people.connections, otherContacts). With domain-wide delegation, a script can maintain a delegated mailbox's contact list from a source of truth (e.g. a Sheet or CRM export). Details in Topic 10 — API & Automation.
