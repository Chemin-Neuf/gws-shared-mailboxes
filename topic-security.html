Comparison across the 7 options

Option MFA / 2FA Compatibility Credential Exposure Offboarding Speed (Revoking One Person) Individual Accountability
1. Shared Password Account Broken 2FA codes must be shared/relayed; concurrent logins trigger lockouts High password known by N people, often written down Slow change the password + re-enroll 2FA + redistribute to everyone None all actions map to one identity
2. Gmail Delegation Account Full each delegate uses their own 2FA None the mailbox password is never shared (can be random + vaulted by admin) Instant remove the delegate grant Strong audit logs record the acting delegate
3. Collaborative Inbox Full personal accounts with personal 2FA None no credentials involved Instant remove from group Strong assignment and posting are attributed
4. Distribution List Full personal 2FA None Instant remove from group Partial membership known; who replied is not centrally visible
5. Email Alias / Redirection Full personal 2FA None Instant remove alias/routing Yes single accountable recipient
6. "Send Mail As" Config Full personal 2FA None Instant remove the sendAs grant Partial sent mail lives in personal Sent folders
7. Email-to-Google Chat Space Full personal 2FA None Instant remove from Space Yes all discussion attributed per author

Policy directive: shared passwords are never acceptable

Option 1 fails every row of this table. Beyond the technical lockouts, shared credentials void individual accountability — unacceptable for an organization handling donor data and subject to GDPR-style obligations. Where a "shared account feel" is truly required, Delegation (option 2) delivers the same UX without sharing any secret. See the synthèse managériale for the governance wording.

Edition limits — Google Workspace for Nonprofits

  • No DLP (Data Loss Prevention) — rules scanning outbound mail for sensitive content require higher editions; not available on GWN regardless of the sharing option chosen.
  • No Google Vault — see Topic 5; retention is architectural, not policy-driven.
  • Available and usable: 2-Step Verification enforcement (free), security keys, context-aware access basics, Admin audit logs (login, admin actions, Groups audit, Gmail log search with limited retention), and alert center.

Administrator perspective

Web console

The Admin console covers: 2SV enforcement per OU, group membership and roles, delegation review (per user: Gmail settings; centrally: report), session revocation, and audit logs. Delegation grants can be inspected via the admin controls covered in Topic 9.

API & automation

Offboarding is highly scriptable: one GAM command chain can remove group memberships, revoke delegation grants, and revoke tokens for a departing user. Details in Topic 10 — API & Automation.
