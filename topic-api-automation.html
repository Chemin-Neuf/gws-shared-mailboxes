Topic 10 — API Capabilities & Automation

Everything an admin can do from a script: provisioning, permission sync, offboarding, reporting. Maps each option to the relevant Google APIs and to GAM, the standard open-source automation tool for Google Workspace.

The API landscape

API Covers Typical Use in This Study
Admin SDK — Directory API Users, groups, members, aliases, shared external contacts Create groups, sync membership from a source of truth, manage aliases, maintain shared contacts
Admin SDK — Groups Settings API Group behavior (posting rights, archive, moderation, Collaborative Inbox flag) Standardize group configuration; enforce baseline settings across all groups
Admin SDK — Reports API Audit events (login, admin, groups, token) Delegation inventory reports, offboarding verification
Gmail API Per-mailbox settings: delegates, sendAs identities, signatures, labels, filters; message read/export Provision delegates + sendAs + signatures centrally; export a delegated mailbox for archival
People API Per-account personal contacts Feed a delegated mailbox's contact list from a Sheet/CRM export

Most mailbox-level Gmail API operations require a service account with domain-wide delegation (a one-time admin setup in the console). This is the standard, free, Google-supported pattern — no third-party tool involved.

Comparison of API capabilities and automation across the 7 options

Option Provision via API Permission / Access Sync Not Scriptable
1. Shared Password User creation only Nothing meaningful Password distribution (that's the problem)
2. Delegation Full user + delegates + sendAs + signature + labels Full delegate list sync from a Sheet/HR source Nothing significant — best API story of all options
3. Collaborative Inbox Full group + settings + members Full membership sync Assignment & resolved status (UI-only, no API)
4. Distribution List Full Full membership sync Members' personal filters/labels (per-account, scriptable per user only)
5. Alias / Redirection Full user aliases (Directory API / GAM) N/A Routing / redirection rules (Admin console only — no API; only per-user auto-forwarding is scriptable)
6. Send Mail As Full via Gmail API sendAs (with domain-wide delegation) Provision + audit who may send as what User's manual From-selection habit
7. Email-to-Chat Space Partial Space management via Chat API; inbound email webhook setup is manual Membership via Chat API The email-ingestion piece (app script / webhook) is bespoke

GAM — the practical automation layer

GAM (open source, free, actively maintained) wraps these APIs in a command line — the de facto standard for Google Workspace administration. Representative commands:

# Create a Collaborative Inbox group gam create group support@example.org name "Support Team" gam update group support@example.org collaborative inbox # Attach a shared alias address to a user account (option 5) gam create alias support@example.org user jane.doe@example.org # Add a delegate to a functional mailbox gam user compta@example.org delegate to jane.doe@example.org # Provision a "Send Mail As" identity + standard signature for a member gam user jane.doe@example.org add sendas support@example.org "Support Team" replyto support@example.org # Inventory all delegations in the tenant (reporting) gam all users show delegates # Offboard: strip group memberships and delegation grants gam user leaver@example.org delete groups gam all users delete delegate leaver@example.org

Caution — delegated-mailbox contact hygiene: when syncing contacts into a delegated mailbox via the People API, keep the source of truth outside Google (Sheet/CRM) and treat the mailbox's list as a replica.

Policy fit

All of the above uses Google's own APIs and a free open-source CLI — fully within the nonprofit external-tools policy: no recurring cost, no additional vendor with data access, and skills transferable to any Google Workspace tenant.
