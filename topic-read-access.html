Topic 1 — Read Access & Platform Compatibility

Where and how can team members actually read the shared address's mail? Web browser, desktop email client, native mobile app — and does the shared traffic stay separate from personal mail or blend into it?

Comparison of read access and platform compatibility across the 7 options

The table below maps each option against the four reading contexts a team member may use. "Personal client/app" means the mail arrives in the member's own mailbox and is read with whatever tool they already use.

Option Desktop Web Browser Desktop Email Client Mobile App (Android/iOS) Key Read Caveats & Inbox Distinction
1. Shared Password Account Yes mail.google.com Yes IMAP / GWSMO1 Yes Gmail / native apps Dedicated inbox. Caveat: simultaneous multi-location logins trigger severe 2FA/security lockouts. Pinned mobile web shortcuts are fragile.
2. Gmail Delegation Account Yes Gmail account switcher No IMAP not supported for delegates Yes native Gmail app2 Dedicated inbox in a separate view. Caveat: dynamic session indices (/u/0/, /u/1/) make pinned mobile web shortcuts unusable.
3. Collaborative Inbox Yes groups.google.com No No standalone app Isolated in the Groups web UI. Mobile web access possible via a pinned URL, but the UI is desktop-oriented and clunky.
4. Distribution List Yes personal Gmail Yes personal client Yes personal app Major caveat: no default visual differentiation between personal and group emails inside the inbox — requires manual filters/labels.
5. Email Alias / Redirection Yes personal Gmail Yes personal client Yes personal app Major caveat: incoming alias messages blend directly into the primary inbox with no default visual separation — requires user rules.
6. "Send Mail As" Config N/A outbound focus N/A N/A Outbound capability paired with option 4 or 5. Inbound reading behavior — and lack of default separation — is inherited from the underlying Group/Alias.
7. Email-to-Google Chat Space Yes chat.google.com / Gmail Chat No Yes Google Chat / Gmail app Isolated inside a dedicated Chat space thread with push notifications. Not formatted as a standard email inbox.
  1. GWSMO — Google Workspace Sync for Microsoft Outlook. A free Google utility for Windows that synchronizes a Workspace account's mail, calendar and contacts with the Microsoft Outlook desktop client, without manual IMAP configuration. Relevant here only to the Shared Password Account: it cannot help delegates, because delegated mailboxes expose no IMAP/Outlook access at all.
  2. Delegation in the Gmail mobile app is brand new. Native access to a delegated mailbox in the Gmail app (Android/iOS) was introduced by Google in summer 2026 and is still rolling out progressively — it may not yet be available on every account or device. Until rollout completes on your tenant, verify availability per user and treat the mobile browser as the fallback.

User perspective

Reading context shapes daily habits more than any other criterion:

  • Known environment vs new environment. Options 4–6 keep users in their familiar personal mailbox; options 1–3 and 7 require switching to another account, another tab (Groups), or another tool (Chat).
  • Inbox separation is a double-edged sword. A separate inbox (options 1, 2, 3, 7) prevents confusion between personal and shared mail, but users must remember to check it. Blended delivery (options 4, 5) guarantees visibility but risks personal/shared mix-ups without filter discipline.
  • Mobile reality check. For staff in the field, only options delivered to the personal mailbox (4, 5), the Gmail app delegation view (2), or Chat (7) are practical on a phone.

Blocking criterion

If your team must read shared mail in a native mobile app, the Collaborative Inbox as primary interface is eliminated (email-delivery fallback remains). If your team must use Outlook or Thunderbird, Delegation, Collaborative Inbox and Chat Space are eliminated for reading. See the Decision Guide for the full logic.

Administrator perspective

Web console

No read-access setting is exposed per option beyond what the option fundamentally is: group delivery settings (Groups admin), delegation grants (user-level, with an admin-level API), and routing rules (Gmail routing in the Admin console) for aliases/redirection.

API & automation

Read access itself is not administrable via API — it follows from the architecture. What is scriptable: group membership (Admin SDK Directory), group delivery settings (Groups Settings API), and delegate grants (Gmail API users.settings.delegates). Details in Topic 10 — API & Automation.
