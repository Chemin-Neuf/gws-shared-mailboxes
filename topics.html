The 10 evaluation topics

1. Read Access & Platform Compatibility

Web, desktop clients (IMAP/Outlook/Thunderbird), mobile apps; inbox separation vs blending with personal mail.
2. Reply & Writing Dynamics

Outbound capabilities, shared vs personal Sent folder, draft sharing and co-editing.
3. Folder & Label Organization

Gmail labels vs IMAP folders vs Groups tags; whether organization syncs across the team.
4. Team Collaboration & Status Visibility

Read/reply status shared across members, assignment to individuals, resolved marking, duplicate-reply avoidance.
5. History, Search & Archiving

Centralized search over past conversations, retention, offboarding continuity. Includes GWN edition limits (no Vault).
6. Sender Identity & Signatures

"On behalf of" headers, shared vs personal signatures, From-address control per option.
7. Contacts & Directory Access

Autocomplete behavior, domain Directory, shared external contacts, contact delegation as a cross-option building block, third-party gap analysis.
8. Security, Offboarding & Compliance

MFA compatibility, credential exposure, access revocation speed, DLP availability per edition, plus a verified federated-SSO pattern for short-term external access.
9. Admin Controls & Governance

Audit logs and their fixed retention windows, delegation tracking, membership/permission management via the Admin console web UI.
10. API Capabilities & Automation

Admin SDK, Gmail API, Groups Settings API; GAM scripting; provisioning and permission-sync automation.

Blocking criteria — quick reference

Some requirements are blocking: if your team needs them, certain options are eliminated immediately, regardless of their other strengths. The full decision logic with workarounds lives in the Decision Guide.

If you need… Eliminates Surviving options / workaround
Native mobile app access Collaborative Inbox (web UI only) Delegation via Gmail app, Distribution List, Alias; or receive Group posts by email.
Shared Sent folder visible to the whole team Distribution List, Alias, Send-Mail-As Delegation or Shared Account; enforced workaround for the Groups options: admin outbound compliance rule copying (BCC) replies to the group address — manual CC is discipline-dependent and fails silently.
Central read/unread status Distribution List, Alias Delegation, Shared Account, Collaborative Inbox (assignment-based, not read-state).
Zero extra license (cost / user-cap pressure) Delegation, Shared Account (1 license each) All Groups-based options, Aliases, Chat Space.
Desktop client (Outlook / Thunderbird) Collaborative Inbox, Delegation, Chat Space Shared Account (IMAP/GWSMO), Distribution List, Alias (via personal client).
Individual accountability (audit trail per person) Shared Password Account All other options; shared credentials are a policy violation regardless.

Standing constraint — external tools

Nonprofit resource policy

As a Google Workspace for Nonprofits tenant with limited financial and administrative resources, the default answer to third-party tools and plugins is no. Exceptions are considered only when a tool is (a) free, (b) provides a really considerable functional addition that native Google features cannot cover, or (c) can be deployed to a limited set of users only (e.g. VIP or power users), without tenant-wide cost or maintenance burden. Every topic page flags external-tool dependencies against this policy.
