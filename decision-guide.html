Decision Guide — Blocking Criteria & Workarounds

Start from what your team absolutely needs. Each blocking criterion below eliminates options immediately; the workarounds show what remains and at what cost. Answer the questions in order — the first "yes, we need that" usually decides.

On this page

How to use this guide

For each shared address you want to set up, walk through the blocking criteria below with the future users. As soon as a criterion is a hard requirement, the options listed as eliminated are out for that address — regardless of their other qualities. Among the survivors, pick by consulting the option profiles and the topic detail pages.

Different addresses on the same tenant can legitimately use different options — this is a per-address decision, not a tenant-wide one.

The blocking criteria

Blocking requirement Eliminates Survivors & workaround
B1. Native mobile app access
Field staff read and answer on phones, in an app — not a mobile browser.		 Collaborative Inbox (3) as primary interface Delegation via Gmail app, Distribution List, Alias. Workaround for (3): members receive posts by email and process them in the Groups web UI later.
B2. Shared Sent visibility
Anyone on the team can see what was answered, without asking.		 Distribution List (4), Alias (5), Send-Mail-As (6) Delegation (2), Shared Account (1). Enforced workaround for the Groups options (3, 4): admin outbound compliance rule copying (BCC) replies to the group address — see Topic 2. Manual CC is not an option: discipline-dependent, fails silently.
B3. Central read/unread state
"Already handled?" must be visible on the message itself.		 Distribution List (4), Alias (5), Send-Mail-As (6) Delegation (2), Shared Account (1). Partial: Collaborative Inbox (3) tracks assignment/resolution instead of read state — often the better model anyway.
B4. Task assignment & queue workflow
Support-desk style: owners, status, "resolved".		 All except Collaborative Inbox (3) Collaborative Inbox (3). Workaround for mailbox options: label conventions ("Assigned:Jane") — works but has no enforcement and no dashboard.
B5. Zero additional license
No budget headroom and/or staying clear of the 2,000-user cap.		 Delegation (2), Shared Account (1) All Groups-based options (3, 4), Alias (5), Send-Mail-As (6), Chat Space (7).
B6. Desktop email client (Outlook / Thunderbird)
Users standardized on a real IMAP/Exchange client.		 Collaborative Inbox (3), Chat Space (7); Delegation (2) for Thunderbird/IMAP — it survives only via GWSMO on Windows + Outlook Shared Account (1) via IMAP/GWSMO; realistically: Distribution List / Alias delivered into the personal mailbox, which the client already reads. Delegation (2) works only if the team is on Windows + Outlook (GWSMO "Add account for delegation" — see Topic 1).
B7. Individual accountability (audit trail per person)
Every read/reply attributable — donor data, GDPR posture.		 Shared Password Account (1) All other options. Note this criterion is absolute: option 1 is excluded by policy regardless of any other consideration. The one sanctioned deviation is the bounded federated-SSO exception for short-term external access — see Topic 8; it requires explicit governance sign-off and sets no precedent.
B8. Compose new external mail as the shared identity
Not just replying — initiating contact with arbitrary recipients.		 Collaborative Inbox (3) alone, Chat Space (7) alone Delegation (2), Alias/Send-Mail-As (5, 6). Hybrid: Collaborative Inbox (3) for intake + Send-Mail-As (6) for new outbound — a common combination; with centrally provisioned Send-As (Gmail API) plus the outbound compliance rule, this hybrid becomes the enforced workaround of Topic 2.

Typical recipes by use case

Support / helpdesk queue

Many incoming requests, team triage, need "who handles this" and "done". → Collaborative Inbox (3), optionally + Send-Mail-As (6) for new outbound. Free.

Functional mailbox (compta@, secretariat@)

One identity, full correspondence history, 2–5 people, auditability required. → Delegation (2). Costs 1 license — justified here.

Announcement / information list

Broadcast to a team; replies rare; no shared state needed. → Distribution List (4). Free, zero friction.

Role address held by one person (president@)

Single owner, reassigned occasionally. → Alias (5) on the person's account. Reassignment = move the alias.

Field team on phones, light volume

Mobile-first, no desk workflow, tolerance for blended inbox. → Delegation (2) via the Gmail mobile app (delegation is now fully supported there), or Distribution List (4) + Send-Mail-As (6) if shared Sent visibility doesn't matter.

Internal triage before external answer

Discuss among the team, then one person answers from Gmail. → Email-to-Chat Space (7) + Send-Mail-As (6).

When nothing survives

If B6 (desktop client) combines with B2/B3 (shared state), no native option survives — that is the actual gap Microsoft shared mailboxes used to fill. The least-bad answers are Delegation (2) with a web-Gmail habit change, or a Shared Account (1) confined to the single Outlook workstation — with its security caveats formally accepted by management. Document the choice; revisit if the edition is ever upgraded.
